# Stage 4: Reading requests

## A client sends the header "x-request-source: cli". Which lookup finds it?
* r.Header.Get("X-Request-Source")
* r.Header.Get("x-request-source")
* r.Header["X-Request-Source"]
- r.Header["x-request-source"]
> Go stores header names in canonical form (X-Request-Source). Get, Values,
> Set, Add and Del canonicalise the name you pass; direct map indexing does
> not, so you must use the canonical key yourself.

## What does r.Header.Get("Host") return in a server handler?
- The Host header value
* "" (the server moves Host into r.Host)
- The server's own hostname
> For incoming requests the Host header (or HTTP/2's :authority) is stored
> in r.Host and removed from r.Header.

## A request arrives for http://localhost:8080/get?x=1 over plain HTTP/1.1. What is r.URL.Host on the server?
- "localhost:8080"
* "" (the request line only had "/get?x=1")
- "localhost"
- "http://localhost:8080"
> On the server, r.URL is parsed from the request target, which is normally
> just path and query. Use r.Host for the host and r.TLS to know the scheme.

## For ?tag=a&tag=b, what does r.URL.Query().Get("tag") return?
* "a"
- "b"
- "a,b"
- []string{"a", "b"}
> Get returns the first value. Index the url.Values map (q["tag"]) to get
> every value.

## r.RemoteAddr is "[::1]:52341". What is the cleanest way to get "::1"?
- strings.Split(r.RemoteAddr, ":")[0]
* net.SplitHostPort(r.RemoteAddr)
- r.RemoteAddr[:strings.Index(r.RemoteAddr, ":")]
- url.Parse(r.RemoteAddr)
> IPv6 addresses contain colons, so naive splitting breaks.
> net.SplitHostPort understands the bracket syntax.

## Why shouldn't a server blindly use X-Forwarded-For as the client's IP?
- It's deprecated
* Any client can send that header with any value; trust it only when your own proxy sets it
- Go removes it before the handler runs
- It contains the server's IP, not the client's
> Headers are client-controlled. Only a proxy you operate (whose address you
> can check via RemoteAddr) should be trusted to report the original client.

## What does json.Marshal produce for a nil map[string][]string?
- {}
* null
- []
- An error
> nil maps and slices encode as null; empty, non-nil ones as {} and [].
> Initialise them if clients expect an object or array.

## In what order must a handler do these to return JSON with status 201?
* w.Header().Set("Content-Type", ...), then w.WriteHeader(201), then write the body
- w.WriteHeader(201), then w.Header().Set(...), then write the body
- Write the body, then w.WriteHeader(201), then set headers
> Headers are sent with the status line. After WriteHeader (or the first
> Write), header changes are ignored, and the status can't change.

## Which method of *url.URL gives the path plus the encoded query, e.g. "/get?a=1"?
= RequestURI
= RequestURI()
= r.URL.RequestURI()
= url.URL.RequestURI
= URL.RequestURI
> url.URL.RequestURI returns the encoded path?query (or opaque) form, which
> is exactly what a client puts in its request line.
