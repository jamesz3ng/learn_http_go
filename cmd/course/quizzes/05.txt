# Stage 5: Building requests

## You build a request without setting User-Agent. What does Go's client send?
- No User-Agent header at all
* User-Agent: Go-http-client/1.1
- User-Agent: Go/1.24 net/http
> If req.Header has no User-Agent key, the client sends its default,
> Go-http-client/1.1 (or Go-http-client/2.0 over HTTP/2). To send no
> User-Agent at all, set it to the empty string.

## How do you make Go's client send NO User-Agent header?
- req.Header.Del("User-Agent")
* req.Header.Set("User-Agent", "")
- req.UserAgent = ""
- It's impossible
> Deleting the key means "use the default". A present-but-empty value means
> "send nothing" (see the comment in (*Request).write in net/http/request.go).

## You set req.Header.Set("Host", "example.test"). What Host does the server see?
* The host from the URL
- example.test
- Both, as two Host headers
> On the client, the Host comes from req.Host if non-empty, otherwise from
> req.URL.Host. The Host key in req.Header is ignored, so set req.Host
> instead.

## You didn't set Accept-Encoding. What happens when the server returns a gzip-compressed body?
* Go asked for gzip and decompresses it for you
- You get the compressed bytes and must gunzip them
- Nothing: Go never asks for compression unprompted
- The request fails, as gzip wasn't requested
> The Transport adds Accept-Encoding: gzip and decompresses for you
> transparently (resp.Uncompressed is then true), unless
> you set Accept-Encoding yourself (or DisableCompression). Then you get the
> raw bytes.

## Which line sends TWO X-Tag headers, "a" and "b"?
```go
req.Header.Set("X-Tag", "a")
// ???
```
- req.Header.Set("X-Tag", "b")
* req.Header.Add("X-Tag", "b")
- req.Header.Set("x-tag", "b")
> Set replaces all values, even when you spell the name in lower case
> (Set canonicalises it to X-Tag); Add appends.

## Why sort header names before printing them?
- HTTP requires headers in alphabetical order
* Go map iteration order varies from run to run
- fmt can't print an http.Header unless it's sorted
> Go maps have no defined iteration order, so unsorted output would change
> from run to run. Map iteration order is deliberately randomised.
> slices.Sorted(maps.Keys(h)) gives stable, testable output.

## What does a HEAD response contain?
* The status line and headers that GET would return, but no body
- Only the status line
- The full body, like GET
- Only headers the server chooses to send for HEAD
> HEAD is "GET without the body". Content-Length may describe the body a GET
> would return. Go's server discards anything a handler writes for HEAD.

## What does a type need to be usable with fs.Var for a repeatable flag?
- A Parse(string) error method
* String() string and Set(string) error
- To be a []string or a map[string]string
> flag.Value has String and Set. Each occurrence of the flag calls Set, so
> appending in Set makes the flag repeatable.

## For `gocurl http://x/ -X PUT`, why doesn't a single fs.Parse(args) see -X?
- Flags with values must be written -X=PUT
* Parsing stops at the first non-flag argument
- PUT is not in the flag package's method list
> Parsing stops at "http://x/", leaving "-X PUT" in fs.Args(). To accept
> flags anywhere, take the positional argument and parse the rest again.
