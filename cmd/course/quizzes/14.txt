# Stage 14: Cookie jars and credentials

## A default http.Client (Jar is nil) follows a 302 that has a Set-Cookie header. Is the cookie sent on the next hop?
- Yes, the client always stores cookies
* No: without a Jar the client ignores Set-Cookie
- Only for same-host redirects
> Cookie handling is opt-in: set Client.Jar (e.g. cookiejar.New(nil)).

## Which two methods make up the http.CookieJar interface?
* SetCookies(u *url.URL, cookies []*http.Cookie)
* Cookies(u *url.URL) []*http.Cookie
- Save(path string) error
- Get(name string) *http.Cookie
> The client calls Cookies before each request and SetCookies after each
> response. Persistence isn't part of the interface.

## How should "-u alice:s3:cret" be split?
* user "alice", password "s3:cret" (split at the first colon)
- user "alice:s3", password "cret"
- It's invalid: too many colons
> Basic auth's user-id can't contain ':' but the password can, so split at
> the first colon (strings.Cut).

## What does cookiejar.New(nil) lack compared with a browser's cookie store?
* A public suffix list, so it can't stop a site setting cookies for a public suffix like co.uk
- Support for the Secure attribute
- Support for expiry
- Thread safety
> golang.org/x/net/publicsuffix provides one. Without it, the jar still
> follows domain, path, expiry and Secure rules.

## Which line adds a cookie to an outgoing request without a jar?
* req.AddCookie(&http.Cookie{Name: "a", Value: "1"})
- http.SetCookie(req, &http.Cookie{...})
- req.Cookies = append(req.Cookies, ...)
> AddCookie appends to the Cookie header. http.SetCookie is for
> ResponseWriters (Set-Cookie).

## You reuse one http.Client with a jar for two separate Do calls to the same site. Does the second request carry cookies set by the first response?
* Yes, the jar lives as long as the client
- No, jars are per request
- Only if the first response was a redirect
> The jar is shared state on the client, which is how a Go program can stay
> "logged in" across requests.

## Where does Go's client store a Bearer token you want sent?
- req.SetBearer(token)
* req.Header.Set("Authorization", "Bearer "+token)
- http.Client{Token: token}
> There's no special API: it's just a header. (A RoundTripper can add it to
> every request: stage 16.)
