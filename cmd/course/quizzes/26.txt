# Stage 26: Capstone: a load-balancing reverse proxy

## Which of these are hop-by-hop headers that a proxy must not forward?
* Connection
* Keep-Alive
* Transfer-Encoding
* Upgrade
- Authorization
- Content-Type
> Hop-by-hop headers describe a single connection. Headers named in the
> Connection header are hop-by-hop too.

## A request carries "Connection: X-Secret" and "X-Secret: 1". Should a proxy forward X-Secret?
* No: listing it in Connection makes it hop-by-hop
- Yes, it's a custom header
> Senders use Connection to mark extra headers as connection-specific;
> proxies must remove them.

## Why should a proxy send backend requests with a RoundTripper rather than an http.Client?
* A Client follows redirects and applies a cookie jar; a proxy must pass 3xx responses and Set-Cookie through to its client
- Clients can't send request bodies
- RoundTrippers are faster
> The proxy's own client is the one that should decide about redirects and
> cookies.

## What should a proxy answer when it can't reach any backend?
= 502
= 502 Bad Gateway
> 502 means the gateway (proxy) got no valid response from upstream; 504
> means upstream was too slow.

## When is it safe to transparently retry a request on another backend?
* When the connection to the first backend failed (the request was never sent) and the request has no body to re-send
- Always, for any error
- Only for POST requests
- Never
> If the first backend received the request, it may have acted on it. An
> inbound body is a one-shot stream, so body-less requests are the safe case.

## What does httputil.ProxyRequest.SetURL do to the outbound Host header?
* Sets it to the target's host (the original host can still travel in X-Forwarded-Host)
- Keeps the client's Host
- Removes it
> To keep the inbound Host instead, set pr.Out.Host = pr.In.Host after
> calling SetURL.

## Why is Rewrite preferred over Director in httputil.ReverseProxy?
* With Rewrite, client-supplied X-Forwarded headers are stripped first and hop-by-hop removal can't undo your changes
- Director is removed in recent Go versions
- Rewrite is required for streaming
> Director runs before some of ReverseProxy's own header processing, which
> has caused subtle security bugs. Rewrite (Go 1.20) fixes the ordering.

## Two gobin backends each have their own in-memory key-value store behind a round-robin proxy. A client PUTs a key, then GETs it. What happens?
* The GET hits the other backend about half the time and gets 404
- The proxy merges the stores
- The PUT goes to both backends
> Stateful backends need shared storage, replication, or routing that keeps
> each key on one backend (e.g. consistent hashing).

## What does ReverseProxy.FlushInterval = -1 do?
* Flushes to the client after every write from the backend
- Disables flushing
- Flushes once per second
> Streams (text/event-stream, unknown-length bodies) are flushed immediately
> regardless; -1 makes it unconditional.
